# Support

Use the public repository for reproducible, non-sensitive defects and documentation improvements when GitHub Issues are available.

Before reporting a problem:

1. Confirm every Varendo package uses the same exact version.
2. Reduce the issue to the smallest synthetic fixture.
3. Check the relevant component or integration documentation.
4. Record the browser, framework, operating system, exact package versions, expected behavior, and observed behavior.

Use [GitHub private vulnerability reporting](https://github.com/hermawan22/varendo/security/advisories/new) for security issues. Do not include credentials, customer records, proprietary source, or active incident details in public reports.

The open-source project does not currently promise a response-time service level.
