Documentation, runnable examples, defect reports, and focused code changes are
welcome. These public docs are the product reference; contributor setup and
repository rules live alongside the source.

## Make a contribution

1. Read [CONTRIBUTING.md](https://github.com/hermawan22/varendo/blob/main/CONTRIBUTING.md)
   for the pinned toolchain, local setup, commit sign-off, and pull request flow.
2. Read [AGENTS.md](https://github.com/hermawan22/varendo/blob/main/AGENTS.md) for
   package boundaries, code conventions, ownership, and required verification.
3. Use the [technical documentation index](https://github.com/hermawan22/varendo/blob/main/docs/README.md)
   to find architecture and maintenance guidance. Edit canonical Markdown or
   generator sources rather than generated artifacts.
4. Open a focused pull request with a reproducible example, updated docs, and
   fresh output from the checks relevant to the change.

## Report a defect or ask for help

Follow [SUPPORT.md](https://github.com/hermawan22/varendo/blob/main/SUPPORT.md), then
[open a GitHub issue](https://github.com/hermawan22/varendo/issues/new/choose).
Include exact package and environment versions, expected and observed behavior,
and a small reproduction using synthetic data. Remove credentials and customer
records from logs, screenshots, and exported projects.

## Conduct reports

Participation follows the
[Code of Conduct](https://github.com/hermawan22/varendo/blob/main/CODE_OF_CONDUCT.md).
Use GitHub's **Report abuse** control on the relevant content or profile; see
[GitHub's reporting instructions](https://docs.github.com/en/site-policy/acceptable-use-policies/reporting-abuse-or-spam).
GitHub handles those reports under its own policies. This is not a private
project moderation inbox, and the project makes no response-time promise.

## Security reports

Follow [SECURITY.md](https://github.com/hermawan22/varendo/blob/main/SECURITY.md) and
[submit a private vulnerability report](https://github.com/hermawan22/varendo/security/advisories/new).
Keep exploit details and sensitive evidence out of public issues. Include the
version, entry point, affected boundary, and a minimal reproduction. No
monitored security email address or response-time SLA is published.
