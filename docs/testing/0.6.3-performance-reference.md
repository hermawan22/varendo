# 0.6.3 performance reference review

The [owner decision of 1 October 2026](../adr/014-planner-timing-diagnostics.md)
permanently removed the planner timing gate.
This review preserves its original measurements and approval evidence. The
former 16 ms planner p95 criterion is superseded and is no longer a requirement.

## Reviewed source and workload

The maintainer-approved reference is `d90a2c8c11c695439d951b661f4071411e30b9b6`, workload
`c9f7283566889e784043cc07703215c6ca882dfdd45da284dc9849e6326314fb`.
The [same-source probe](https://github.com/Arconath/aeliqo/actions/runs/36768333830)
completed three alternating pairs and twelve layout/2D reports. It compared the
clean source with an independently archived copy of that same source. The
original report remains `stable-probe-unapproved`; approval is recorded
separately by the maintainer in the metadata commit after two independent
reviews of the raw evidence.

The [raw artifact](https://github.com/Arconath/aeliqo/actions/runs/36768333830/artifacts/11123022298)
is artifact `11123022298`, ZIP SHA-256
`3251ae7a2eaec5443372acc1cddd91d1343e5b79676f4f88f71f40245e6a15fa`.
The review compared both 1,778-file source manifests with the exact Git tree's
blob identities and modes, independently recomputed the workload hash, and
checked matching runner environments and all six source-change guards. It
recalculated every planner p95 from all 30 subsequent planner observations and
every reducer p95 from all 3,000 dispatch timings, the layout p95 from each raw
Chromium trace, and the 2D p95 from all 40 mutation/layout observations per run.
The recorded pair order, raw observations, medians, ranges, regression condition,
geometry, selection continuity and absence of interaction network requests all
match the reports. No observations were removed and no budgets changed.

| Pair | Baseline planner p95 | Candidate planner p95 |
| ---- | -------------------: | --------------------: |
| 1    |              14.4 ms |               13.2 ms |
| 2    |              15.8 ms |               13.3 ms |
| 3    |               6.4 ms |               12.8 ms |

All six subsequent planner p95 values passed the historical criterion in effect
for this probe. Subsequent reducer dispatch p95 is 0.3 ms against 4 ms,
and each large-table observation mounts 44 rows against 100. Individual
subsequent planner observations reach 23.6 ms. Planner p95 varies from 6.4 to
15.8 ms within this same-source experiment. The raw observations and traces
preserve that variation and the historical 0.2 ms margin to the former criterion.
Each run also retains its 10 first-labelled planner observations and 1,000 first-labelled reducer dispatch
timings. Their individual maxima reach 27.4 ms and 10.8 ms respectively. These
first/subsequent groups reuse one loaded page; they are not a true cold-cache
measurement. The original absolute p95 assertions applied to the subsequent
samples; the planner assertion has since been removed.

| Relative metric                   | Baseline p95 observations | Candidate p95 observations | Baseline median | Candidate median |
| --------------------------------- | ------------------------- | -------------------------- | --------------: | ---------------: |
| Layout event                      | 3.617, 3.315, 3.456 ms    | 3.611, 3.511, 3.648 ms     |        3.456 ms |         3.611 ms |
| 2D mutation/DOM and forced layout | 41.2, 37.8, 37.2 ms       | 37.2, 38.8, 37.3 ms        |         37.8 ms |          37.3 ms |

Each layout trace contains 14–15 layout events, so nearest-rank p95 equals
the largest event at that sample size. This small event count limits how
precisely the trace percentile describes a broader latency distribution.

The median layout difference is +0.155 ms (+4.485%); the median 2D difference is
−0.5 ms. Both pass the unchanged joint regression condition: more than 20%
**and** more than 2 ms over three-pair medians. The 2D measurement includes DOM
updates and synchronous layout reads; it does not measure paint or
input-to-paint latency. These same-source measurements establish a reference
under the recorded conditions. They do not establish a speedup over an earlier
version, performance on other machines, or a general capacity guarantee.

## Environment and reference renewal

The runner uses immutable Playwright image
`sha256:bc6ab0d6d44ff4826e4cb8c1e6d801e185bfc42bb0753f8e2a30efc70db054c7`,
Linux x64, Node 24.20.0, pnpm 11.24.0 and Playwright 1.63.0. Browser executables,
versions and font hashes match the recorded runner; the layout workload uses
1280×720, en-US/UTC and scale 1, while the 2D workload uses 1440×900,
de-DE/Europe-Berlin and scale 1. The measurement host was an Intel Xeon Platinum
8573C with four logical CPUs and 16,765,378,560 bytes of memory.

The previous [0.6.0 reference](0.6.0-performance-reference.md) records the older
workload `867fadc9677857bbbca368716c9d52a78d97e7e5cb419f66207e1d42ed65c913`.
The current fixture opens the exact-data disclosure before pagination and
checks the current row-count scope text. The workload digest also includes the
bundle probe's previously owner-approved 168 KiB region budget. These tracked
fixture changes invalidated the earlier reference before any measurements ran;
they did not demonstrate a measured regression. The probe retained the budgets
in effect at the time. The planner timing requirement has since been removed; the 4 ms reducer, 100 mounted-row and
20% **and** 2 ms comparison budgets remain unchanged.

A passing probe alone does not qualify the final release. The final clean
source must pass the same-SHA main-push functional and release checks. The
performance CI job remains advisory; claims of paired-performance qualification
require actual successful comparison evidence against the approved baseline,
under the remaining comparison checks.
