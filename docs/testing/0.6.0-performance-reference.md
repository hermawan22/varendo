# 0.6.0 performance reference review

The [owner decision of 1 October 2026](../adr/014-planner-timing-diagnostics.md)
permanently removed the planner timing gate.
This review preserves historical measurements and approval evidence. Its former
16 ms planner p95 criterion is superseded and is no longer a requirement.

## Reviewed reference

The approved reference is `9b0bb0bbddce72c187b9aab1083b1bc1a5a3a893`, workload
`867fadc9677857bbbca368716c9d52a78d97e7e5cb419f66207e1d42ed65c913`.
The [same-source probe](https://github.com/Arconath/aeliqo/actions/runs/36285042648)
completed all three alternating pairs and twelve layout/2D reports. Independent
review verified both 1,772-file source manifests, their exact bytes and modes,
matching runner environments, all six absolute checks and the relative
calculations. A second review recalculated each planner p95 from all 30
subsequent observations and each reducer p95 from all 3,000 dispatch timings.
No observations were removed or budgets changed.

The [raw artifact](https://github.com/Arconath/aeliqo/actions/runs/36285042648/artifacts/10920661000)
has ZIP SHA-256 `bb5cefe6e0587a74f19d886cbe2efdf97b611f8f63337157230ef0c250a5fb86`.
Its original machine report remains unapproved; this review is the separate
approval record used by the comparison gate.

| ---- | -------------------: | --------------------: |
| 1    |              15.8 ms |               13.8 ms |
| 2    |               6.3 ms |               11.7 ms |
| 3    |              11.1 ms |               13.9 ms |

All six passed the historical planner p95 criterion in effect for this probe.
Reducer p95 is 0.3–0.4 ms against 4 ms, and each large-table sample mounts
44 rows against 100. Individual planner maxima include 77, 40.2 and 30.5 ms.
Raw timings and traces preserve these tails.

Median layout-event p95 is 3.201 versus 3.161 ms. Median 2D mutation/layout p95
is 34.8 versus 35.0 ms. Both pass the unchanged joint regression condition:
more than 20% **and** more than 2 ms over three-pair medians. This same-source
probe establishes a reference under those conditions, not a runtime speedup
over an earlier version or a capacity guarantee for another machine.

The runner uses immutable Playwright image
`sha256:bc6ab0d6d44ff4826e4cb8c1e6d801e185bfc42bb0753f8e2a30efc70db054c7`,
Linux x64, Node 24.20.0, pnpm 11.24.0 and Playwright 1.63.0. Executable/font
hashes and workload viewport, locale, timezone and scale are copied exactly
into `scripts/performance/budget.json`. The measurement host was an AMD EPYC
9V74 with four logical CPUs and 16,766,414,848 bytes of memory.

The revised workload formats field names once per data setup while retaining
fresh 10,000-row, 100-field inputs, 30 views and 64 planner candidates on each
iteration. This changes setup allocation pressure and requires its own
reference. Earlier probes failed the former planner criterion at 19.7 ms and
16.8 ms; those failures remain diagnostic history under the policy then in effect.
Later implementation changes reuse internal success signals, owned task analysis
and native property descriptors.
Allocation profiles support lower temporary allocation, but do not establish
the cause of every timing difference.

The performance-probe job passed. An earlier functional run exposed a narrow
dialog-heading issue, and visual qualification remained incomplete. At the time
of this review, the final source was required to pass the paired gate and the
full same-SHA main-push matrix.
The planner timing requirement has since been removed, and performance CI is
advisory. The full same-SHA main-push matrix remains required for publication;
this reference approval does not authorize publication on its own.
