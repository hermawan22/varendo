own enclosing commit or replace final release acceptance. Publication requires

permanently removed the planner timing gate.

effect for these historical runs; they do not reinstate that requirement.

## Performance and final release boundary

The [performance reference review](0.6.0-performance-reference.md) records all
three alternating pairs from the exact-source Linux probe, the absolute
budgets then in effect and the pinned runner. It is reference evidence, not the
final release comparison.

The historical release policy required the final source to pass `policy`,
`functional`, `visual` and `performance`. Current publication requires the
full same-SHA main-push matrix; visual and performance CI are advisory.
RC and stable publication must verify all five registry packages and their
source provenance. Image publication must use that verified source; production
acceptance must record its digest, GitOps revision, health/readiness, public
version, manual and native WebMCP journeys, and export consumer results.
None of these later operations is inferred from the local checks above.
