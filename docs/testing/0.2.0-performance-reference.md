# Varendo 0.2.0 performance reference review

Review date: 20 October 2026. Reference source:
`761f57e85bff9af61ab3fc4d154154514794f829`. Workload:
`3c4c86f0e378fce3306e72f1dc03d1f92130f76d6269e1558e773d80014d1cd8`.

## Why the reference was renewed

The 0.2.0 source renames every remaining former-name identifier to Varendo.
That rename changed the performance workload digest, so the strict comparison on
the rename's main push correctly rejected the changed workload before measuring
anything. That failure was not evidence of a performance regression.

Independent recomputation of all 50 included paths reproduced the new digest.
Compared with the previous reference's last approved candidate
`5177365e3690bd5fee942897a17175ee3b496d4d`, the 55 tracked workload paths keep
the same count and layout: 20 are byte-identical and 35 are identical after
mapping `Aeliqo`/`aeliqo`/`AELIQO` to `Varendo`/`varendo`/`VARENDO` in paths and
contents. No workload exclusion, comparison limit, assertion or measurement
code changed. The [0.1.0 review](0.1.0-performance-reference.md) remains intact.

## Same-source evidence

The owner-dispatched [probe run 39310401938](https://github.com/hermawan22/varendo/actions/runs/39310401938)
compared the clean reference with an independently archived copy of the same
commit. Three pairs ran in baseline/candidate, candidate/baseline,
baseline/candidate order. Both sources were installed from the frozen lockfile
and independently built. The probe reports `stable-probe-unapproved` and
`approved: false`; it does not itself grant approval.

The [raw artifact 12215895948](https://github.com/hermawan22/varendo/actions/runs/39310401938/artifacts/12215895948)
contains all twelve workload reports, six Chromium timeline traces, both source
manifests, environments and the complete comparison. The downloaded ZIP is
11,795,544 bytes; its SHA-256 matches GitHub's artifact digest
`b698ffa6fd295dda9511e9c1f52421955567c9cf47e7dfb1dc4cfe0a75c475a5`, and all 23
members pass CRC verification.

Both 1,832-entry source manifests equal the exact Git tree of the reference,
including modes and blob identities. All six layout reports record unchanged
source bytes. The baseline and candidate environments are identical, and the
reported runner, workload digest and three-pair, relative and absolute policy
equal the committed budget metadata.

## Environment and scope

Both environments match the recorded immutable Playwright container
`sha256:bc6ab0d6d44ff4826e4cb8c1e6d801e185bfc42bb0753f8e2a30efc70db054c7`,
Linux x64, Node 24.20.0, pnpm 11.24.0, Playwright 1.63.0, browser executable
hashes and the 39-file font inventory. Layout uses 1280×720, en-US/UTC and scale
1; 2D uses 1440×900, de-DE/Europe-Berlin and scale 1. The measurement host was
an Intel Xeon Platinum 8573C with four logical CPUs, 16,765,378,560 bytes of
memory and kernel 6.17.0-1022-azure. Hosted CPU models vary between runs, so
absolute timings from different runs are not compared; only same-run pairs are.

The accompanying metadata records acceptance of this exact reference following
the owner-requested settlement of the rename and this evidence review. All
three-pair, relative and remaining absolute budgets are unchanged. This approval
is separate from the diagnostic probe, whose original unapproved result remains
intact.

This source-bound reference does not qualify other machines, browsers or general
capacity. The clean metadata candidate must subsequently pass the ordinary
three-pair comparison against this fixed source, as described in the
[approval procedure](paired-performance.md#bootstrap-and-approval).
Functional CI, package publication and deployment keep their separate gates.
