HOW IT WORKS

Describe once. Ask anything the data can answer.

  1. 1 · Describe

    Your data and what it means

    Fields, a measure, and the views you allow. Your app keeps the records and permissions.

    defineResource({
  id: 'people',
  fields: { team: { role: 'dimension' },
            joined: { role: 'time' } },
  measures: { hires: { aggregate: 'count' } },
  presentation: {
    allowedViews: ['table', 'cards', 'trend', 'bar'],
  },
});
  2. 2 · Ask

    A small typed intent

    From a button, your code, a URL, or an AI agent. It never contains HTML, code, or permissions.

    {
  "kind": "analyze",
  "resource": "people",
  "measures": [{ "id": "hires" }],
  "time": { "field": "joined", "grain": "month" }
}
  3. 3 · Adapt

    A view that fits

    Varendo validates the intent, evaluates the permitted data, and picks an allowed view.

    • browseTable, or cards on a phone
    • analyze + timeTrend chart
    • analyze + dimensionsBar chart
    • detailOne record

THE BOUNDARY

Agents propose. Your app decides.

  • No generated UI. An agent sends a typed intent, never HTML, code, SQL, or permissions.
  • Your rules. Data, identity, routes, and actions stay in your application.
  • Works without AI. Buttons and code use the same path; invalid requests never render.
